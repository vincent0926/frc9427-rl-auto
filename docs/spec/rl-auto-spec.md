# 規格書：強化學習強化 Swerve 自動模式（RL Auto）

> FRC 9427｜個人研究專題｜草稿 v0.1｜2026-11-05

## 0. 一句話

在現有 PathPlanner 自動路線上，加一個用強化學習訓練的**殘差策略（residual policy）**：它在模擬中學會「怎麼跑更快又不偏離路線」，部署到機器人即時修正速度命令，並由安全監控器隨時可退回原本的 PathPlanner 控制。

## 1. 問題陳述

目前自動模式由 PathPlanner 規劃路線、`PPHolonomicDriveController`（固定 PID）跟隨（`src/main/java/frc/robot/subsystems/Swerve/Swerve.java:126`）。為了不偏移，最大速度與加速度限制只能設得保守，結果整段自動比機構極限慢；若把限制拉高，轉彎與急停處會打滑、偏線，後面的射擊位置就跟著錯。

手調速度限制和 PID 只能找到「整條路線一組數字」的妥協點，無法針對每一段（直線可衝、轉角要收）做不同決策。這正是強化學習擅長的：在大量模擬中學出隨狀態變化的控制修正。

## 2. 目標

| # | 目標 | 衡量方式 |
|---|---|---|
| G1 | 縮短自動路線完成時間 | 同一條路線，RL 版比 PathPlanner 基準快 **≥ 10%**（延伸目標 20%） |
| G2 | 不偏離路線 | 全程最大橫向誤差（cross-track error）**≤ 基準值**，且 ≤ 10 cm |
| G3 | 終點準確 | 終點位置誤差 ≤ 5 cm、朝向誤差 ≤ 2°（射擊需要） |
| G4 | 從模擬轉到實機可用 | 模擬改善幅度在實機保留 **≥ 70%**（sim-to-real gap 量化） |
| G5 | 安全 | 實機測試中安全監控器能 100% 在觸發條件下接管，無撞擊事件 |

## 3. 非目標

| 非目標 | 原因 |
|---|---|
| RL 從零規劃整條路線（取代 PathPlanner） | 端到端學習在實機風險高、難除錯；殘差架構保留已知可用的行為當底線 |
| 用 RL 控制射擊、吸球等機構 | 範圍控制，先證明底盤一件事 |
| 在機器人上線上訓練（邊跑邊學） | 實機探索會亂動，安全風險過大；只做離線（模擬）訓練 |
| 視覺即時避障、閃避對手 | 需要對手模型與感測，屬另一個題目 |
| 比賽正式使用 | 專題階段只在練習場驗證；要上比賽需另外通過穩定性評估 |

## 4. 系統架構（建議）

```
┌─ 訓練端（筆電，Python）───────────────────────┐
│ 自寫 Swerve 模擬環境（Gymnasium 介面，NumPy 向量化）│
│   ├ 運動學 + 馬達/輪胎摩擦模型 + 控制延遲      │
│   └ 領域隨機化：摩擦、質量、延遲、電池電壓     │
│ 演算法：PPO 或 SAC（Stable-Baselines3）        │
│ 輸出：小型 MLP 權重 → JSON                     │
└──────────────────────────────────────────────┘
              │ policy.json（放 deploy 資料夾）
              ▼
┌─ 機器人端（roboRIO，Java）─────────────────────┐
│ PathPlanner 參考狀態 ─┐                         │
│ 里程計 / 視覺位姿 ────┼→ RL 策略（純 Java 推論）│
│                       │      ↓ Δv, Δω（有上限） │
│ PPHolonomicDriveController + Δ → 安全監控 → Swerve │
└──────────────────────────────────────────────┘
```

- **觀測**：相對參考點的位置/朝向誤差、目前速度、參考速度與曲率、前方數個參考點（lookahead）、電池電壓
- **動作（4 維，已定案）**：
  - `s`：**時間縮放**，在路線上推進的速率（例如 0.5–1.5 倍參考速度），空間路徑不變
  - `Δvx, Δvy, Δω`：疊加在 `PPHolonomicDriveController` 輸出上的速度修正，用來修偏線
  - 每項都有硬上限；輸出經低通或變化率限制，避免抖動
  - 訓練用**課程學習**降低難度：先只開 `s`，收斂後再解鎖速度修正（上限由小到大）
- **獎勵**：推進進度 − 橫向誤差懲罰 − 打滑/電流懲罰 − 動作抖動懲罰；超過偏線門檻直接終止並重罰
- **推論**：MLP 約 2×64 隱藏層，50 Hz 在 roboRIO 上用純 Java 矩陣乘法即可（每週期 < 1 ms），不需協處理器

## 5. 使用者故事

**研究者（我）**
- 身為研究者，我想在模擬中用同一條 PathPlanner 路線比較基準與 RL 版，以確認 RL 真的有改善再上機。
- 身為研究者，我想調整獎勵函數裡「速度」和「偏線」的權重，以觀察兩者的取捨。
- 身為研究者，我想從 AdvantageKit 日誌重播實機跑的軌跡並與模擬疊圖，以量化 sim-to-real 差距。
- 身為研究者，我想只用理論值與寬範圍隨機化訓練，不必佔用練習時間校正模擬參數。

**操作隊員**
- 身為操作隊員，我想在 Dashboard 上一鍵切換「PathPlanner / RL」，以便出問題時立刻退回。
- 身為操作隊員，我想看到安全監控器何時接管、原因是什麼，以判斷能不能繼續測試。

**邊界情況**
- 身為研究者，當 `policy.json` 缺失或格式錯誤時，我要機器人警告並自動用純 PathPlanner，而不是用零權重亂跑。
- 身為研究者，當視覺位姿跳動（例如 max-jump）時，我要策略不因觀測突變而猛修正。

## 6. 需求

### P0（必須）

| 需求 | 驗收標準 |
|---|---|
| **R1 Swerve 模擬環境（自寫 Python）** | 平面剛體動力學 + 馬達轉矩/速度曲線 + 輪胎摩擦上限（會打滑）+ 控制延遲；NumPy 向量化，一次可跑 ≥ 1000 個環境；通過理論健全性檢查（極速、摩擦/電流限制加速度）；以理論值為中心做寬範圍領域隨機化，不依賴實機校正 |
| **R2 雙基準量測** | 對 ≥ 2 條路線各量兩個基準：**B1 目前保守設定**、**B2 手調極限**（速度/加速度限制與 PID 調到剛好不偏線）。記錄完成時間、最大橫向誤差、終點誤差（模擬與實機各一份）。G1 以 **B2** 判定成功，B1 只作參考 |
| **R3 殘差策略訓練** | 模擬中 G1–G3 達標；在未見過的隨機化參數下仍達標率 ≥ 90% |
| **R4 Java 推論** | 讀 deploy 的 JSON 權重；與 Python 推論結果對同一輸入誤差 < 1e-5（單元測試）；每週期 < 1 ms |
| **R5 安全監控器** | 下列任一條件立即切回純 PathPlanner 並記錄原因：橫向誤差 > 門檻、修正量超限、輸出 NaN、推論逾時、視覺/里程計異常 |
| **R6 動作上限** | 時間縮放 s 與 Δvx、Δvy、Δω 都有硬上限（例如 s ∈ [0.5, 1.5]、Δv ≤ 0.5 m/s、Δω ≤ 1 rad/s），寫在 Constants，不由策略決定 |
| **R7 日誌** | 用 AdvantageKit 記錄觀測、動作、是否接管，可離線重播 |

### P1（應該）

- 用實機日誌自動擬合模擬參數（系統識別）
- 獎勵權重掃描與 Pareto 圖（時間 vs 偏線）
- Dashboard 顯示 RL 修正量即時曲線

### P2（未來，但架構要預留）

- 多條路線共用一個策略（觀測只用相對量，不寫死座標）
- 擴充到動態目標（例如邊走邊瞄準 HUB）
- 紅藍方翻轉（沿用 AutoBuilder 翻轉，策略用相對座標即可）

## 7. 實機測試安全流程

沿用隊上單元零精神：
1. 先在模擬跑通、單元測試全過
2. 架空輪子測方向與修正量上限
3. 場地淨空、有人顧 Driver Station Disable
4. 速度上限 25% → 50% → 75% → 100% 逐步放寬
5. 每階段先跑基準、再跑 RL，同一顆滿電電池（≥ 12.5 V）

**網頁或筆電不能當急停，急停一律用 Driver Station。**

## 8. 成功指標

**領先指標（每次訓練/測試就看得到）**
- 模擬：平均完成時間、最大橫向誤差、終點誤差、達標率
- 實機：安全監控接管次數（目標逐階段下降至 0）

**落後指標（專題結束時）**
- 實機改善幅度（G1）與 sim-to-real 保留率（G4）
- 至少 2 條路線、各 10 次實機重複的統計（平均與標準差）

### 已定案（2026-11-05）

| 決策 | 理由 |
|---|---|
| 量兩個基準（B1 目前設定、B2 手調極限），以 B2 判定成功 | 只跟保守設定比會高估 RL 的貢獻 |
| 動作 = 時間縮放 + 速度修正（4 維），用課程學習逐步解鎖 | 速度修正才能主動修偏線；課程學習降低訓練難度與 sim-to-real 風險 |
| 模擬器自寫 Python | 要平行跑大量環境；可完全控制領域隨機化與打滑模型 |
| 以無須實機數據為主：參數用理論值與程式碼常數，放寬隨機化取代校正 | 不佔練習時間；實機只做最後驗收（G4） |
| 模組速度上限由理論推算 `MaxModuleSpeedMps ≈ 4.64 m/s`，也是時間縮放的天花板 | 原 4.0 m/s 會截掉路線要求的 5.0 m/s；詳見 `rl-sim-design.md` §2 |
