# 設計文件：RL 訓練用 Swerve 模擬器

> 對應規格書 `rl-auto-spec.md` 的 R1｜草稿 v0.1｜2026-11-05

## 1. 這個模擬器要回答什麼

RL 要學「跑多快才不會偏線」，所以模擬器必須正確重現**限制速度的那些東西**，其他可以簡化：

| 必須模擬（會讓車子偏線或變慢） | 刻意不模擬（用隨機化代替或與題目無關） |
|---|---|
| 輪胎摩擦上限 → 打滑 | 碰撞、保險桿、場地元件 |
| 馬達轉矩-速度曲線、Stator 電流限制、電池壓降 | 地毯纖維方向性（改用摩擦係數隨機化） |
| 加減速時的前後載重轉移（影響各輪抓地力） | 3D 翻覆、車體晃動 |
| 轉向模組轉角需要時間（不能瞬間轉到位） | 轉向馬達電流、溫度 |
| 控制延遲（50 Hz 週期 + CAN 延遲） | 吸球、射擊等其他機構 |
| **里程計會因打滑而漂移**；視覺修正有雜訊與延遲 | 對手機器人 |

最後一列最關鍵：機器人只知道「估計位置」，打滑時里程計會騙人。模擬器要同時保留**真實狀態**與**機器人以為的狀態**，否則 RL 會學會利用一個實機不存在的完美位置。

**已處理（2026-11-05，不需實機數據）**：

1. **速度上限由理論推算**：原本 desaturate 用搖桿速度 4.0 m/s，而 Blue1 系列與 Blue3-3 末段路線要求 5.0 m/s，自動模式會一路落後。改成
   `MaxModuleSpeedMps = (11 V − kS) × 0.85 / (12 V / 6.06 m/s) ≈ 4.64 m/s`
   （11 V 為比賽後段電池設計點，15% 電壓留給回授修正）。`MaxDriveVelocityMps = 4.0` 只保留給搖桿與加速度限制器。路線 `maxVelocity` 5.0 → 4.6。這個值也是時間縮放 s 的天花板，模擬器沿用同一常數。
2. **`settings.json` 對齊程式碼**（程式碼為參數最終依據）：質量 60 → 50.6 kg、摩擦係數 1.7 → 0.9、`maxDriveSpeed` 4.96 → 4.64。電流限制維持 95 A：PathPlanner 2026.1.2 在 ≤ 80 A 時會對這些路線生成壞軌跡（0 秒或極短），實際馬達限制仍是 60 A。

## 3. 架構：模擬器 = 物理 + 「機器人軟體的複製品」

```
         ┌───────────────── 50 Hz 控制步（env.step）────────────────┐
 action ─┤ 1. 推進參考時間 τ += s·dt，取樣 PathPlanner 參考狀態       │
 (s,Δv)  │ 2. PP 控制器：v = s·v_ref + kP·e_pos（用「估計位姿」）+ Δv  │
         │ 3. Swerve 軟體：場地→機器人座標、運動學、desaturate、     │
         │    模組最佳化(cos 縮放、反轉 180°)                         │
         │ 4. 延遲佇列（命令晚 1~2 個週期才生效）                     │
         └──────────────────────┬────────────────────────────────────┘
                                ▼ 每個物理子步（2 ms，10 次）
         ┌───────────────────────────────────────────────────────────┐
         │ TalonFX 速度迴路：V = kS·sgn + kV·v_cmd + kP·(v_cmd − v_w) │
         │ 馬達：I = (V − ω_m/Kv)/R，Stator 限流，電池內阻壓降         │
         │ 轉向：PositionVoltage → 轉角一階 + 轉速上限                 │
         │ 輪胎：滑移速度 → 摩擦力（摩擦圓飽和）                       │
         │ 車體：平面剛體 (x, y, θ, vx, vy, ω)，載重轉移               │
         └──────────────────────┬────────────────────────────────────┘
                                ▼
         ┌───────────────────────────────────────────────────────────┐
         │ 感測：輪速+轉角 → 里程計（同 Swerve.updateOdometry）        │
         │ 陀螺儀：真實 yaw + 漂移雜訊                                 │
         │ 視覺：隨機頻率、延遲、雜訊、掉幀 → 同 VisionBlendGain 融合  │
         └──────────────────────┬────────────────────────────────────┘
                                ▼
         觀測 obs ← 估計狀態    獎勵 reward ← 真實狀態
```

- **觀測用估計值、獎勵用真實值**：策略只能看到實機也拿得到的資訊；但「有沒有偏線」用真實位置判定，RL 才會學會避免打滑（打滑時里程計看起來沒事，真實位置卻偏了）。
- **第 2、3 步是 Java 程式的 Python 移植**，必須跟實機邏輯一致。每個移植函式都要有「同輸入、同輸出」的對照測試（Java 端輸出測試向量 CSV，Python 讀進來比對）。

## 4. 物理模型

### 4.1 車體

平面剛體，狀態 `(x, y, θ, vx, vy, ω)`（場地座標）：

```
m · a = Σ F_i                       （四輪地面力，場地座標）
J · α = Σ (r_i × F_i)               （r_i：模組位置）
```

J 先用 PathPlanner 設定的 6.88 kg·m² 當初值，之後由轉向測試校正。

### 4.2 載重轉移（決定每輪能抓多少）

```
N_i = m·g/4 − m·a_x·h / (2·L) · sgn_x(i) − m·a_y·h / (2·W) · sgn_y(i)
```

h 是重心高度（未知，隨機化 0.15–0.35 m）；a 用上一個子步的加速度（避免代數迴圈）。N_i 下限為 0。

### 4.3 輪胎（最重要）

每個模組在輪子座標下算接觸點滑移：

```
v_c   = 接觸點對地速度（車體速度 + ω × r_i，轉到輪子方向）
s_lon = v_wheel − v_c,lon          （輪面線速度 − 對地縱向速度）
s_lat = − v_c,lat                  （側滑）
F_raw = C · (s_lon, s_lat)         （線性區）
F     = F_raw · min(1, μ·N_i / |F_raw|)   （摩擦圓飽和）
```

- C 取「約 0.05 m/s 滑移就飽和」：C ≈ μ·N / 0.05
- **數值穩定性**：輪子的等效質量很小（反射轉子慣量），C 又很大，顯式積分會發散。輪速更新對 C 項用**隱式（backward Euler）**，單一純量方程式有封閉解；車體用半隱式 Euler 即可。這點要用單元測試確認（見 §7）。

### 4.4 驅動馬達（Kraken X60，FOC 關閉）

```
TalonFX 速度迴路（每子步）：V = kS·sgn(v_cmd) + kV·v_cmd + kP·(v_cmd − v_w)，限制在 ±V_bat
馬達電流：I = (V − ω_m / Kv) / R，|I| ≤ Stator 限制 60 A
輪子轉矩：τ = I · kT · G · η
輪子轉動：J_w · ω̇_w = τ − F_lon · r
```

Kv、kT、R 從 Kraken X60 非 FOC 規格推（自由轉速約 6000 rpm），**以官方 datasheet 為準**。η（齒輪效率）與 J_w（含反射轉子慣量）是校正參數。

### 4.5 轉向與電池

- 轉向：`θ̇ = clamp((θ_target − θ)/τ_steer, ±ω_steer,max)`，ω_steer,max ≈ Kraken 自由轉速 / 26.09 ≈ 24 rad/s；τ_steer 校正
- 電池：`V_bat = V_oc − R_bat · ΣI`，V_oc 隨機 12.0–12.8 V，R_bat ≈ 0.015–0.025 Ω

### 4.6 積分

| 層級 | 頻率 | 說明 |
|---|---|---|
| 控制步（env.step） | 50 Hz | 與 roboRIO 相同 |
| 物理子步 | 500 Hz（2 ms × 10） | TalonFX 實際是 1 kHz；500 Hz 若與 1 kHz 參考解差異 < 1% 就採用，否則改 1 kHz |

## 5. 參考路線：直接用 PathPlanner 產生

不要在 Python 重寫 PathPlanner 的軌跡生成器（太容易跟實機不一致）。改成：

1. 寫一個小 Java 工具（放 `src/test` 或 Gradle task），用 PathPlannerLib 讀 `deploy/pathplanner/paths/*.path`
2. 用同一份 `RobotConfig` 生成軌跡，以 5 ms 取樣輸出 CSV：`t, x, y, θ, vx, vy, ω, ax, ay, curvature`
3. Python 讀 CSV，以參考時間 τ 插值

時間縮放 s 的含義：`dτ/dt = s`，所以參考速度 × s、參考加速度 × s²（空間路徑不變）。

## 6. 領域隨機化（每個 episode 重抽）

**原則：以理論值為中心、放寬範圍，取代實機校正。** 策略要在整個範圍內都表現好，因此不需要知道真實參數；代價是策略較保守。實機只用於最後驗收（G4）。

| 參數 | 範圍（以理論值 / 程式碼常數為中心） |
|---|---|
| 摩擦係數 μ | 0.6–1.2（程式碼值 0.9） |
| 質量 | 48–58 kg（程式碼值 50.6，含電池、保險桿差異） |
| 重心高度 h | 0.15–0.35 m |
| 轉動慣量 J | 0.6–1.4 × 理論值（均勻質量矩形估算） |
| 齒輪效率 η | 0.80–0.97 |
| 控制延遲 | 0–3 個週期（+ 0–5 ms 抖動） |
| 電池開路電壓 / 內阻 | 12.0–12.8 V / 0.015–0.025 Ω |
| 各模組 kS、kV 誤差 | ±10% |
| 輪徑誤差（磨耗） | ±2% |
| 陀螺儀漂移 | 0–0.5 °/s 隨機遊走 |
| 視覺 | 頻率 5–20 Hz、延遲 30–80 ms、σ 2–8 cm、掉幀 0–50% |
| 起點誤差 | ±5 cm、±2° |

## 7. 驗證（R1 的驗收方式）

**單元測試（pytest，CI 每次跑）**

| 測試 | 預期 |
|---|---|
| 靜止不動 | 無命令時位置漂移 < 1 mm / 10 s |
| 極速 | 直線全油門收斂到 ≈ 自由轉速 × η 對應的速度 |
| 加速度上限 | μ 很低時，最大加速度 ≈ μ·g（受摩擦限制） |
| 對稱性 | 左右鏡像命令 → 鏡像軌跡 |
| 子步收斂 | 500 Hz 與 2 kHz 參考解位置差 < 1% |
| 決定性 | 同 seed 兩次結果完全一樣 |
| 向量化一致 | 1000 個環境批次跑 = 逐一跑的結果 |
| Java 對照 | 運動學、desaturate、模組最佳化、PP 控制器、里程計與 Java 測試向量誤差 < 1e-5 |

**理論健全性檢查（取代實機校正，不需實機數據）**

| 檢查 | 理論預期 |
|---|---|
| 直線全電壓極速 | ≈ (V_bat − kS) / 1.98 V·s/m，12 V 時約 5.9 m/s |
| 摩擦限制加速度 | ≈ μ·g（μ = 0.9 時約 8.8 m/s²），電流限制可能更早觸頂 |
| 電流限制加速度 | 4 × 60 A × kT × G / r / m |
| 原地旋轉角加速度 | 由輪力 × 力臂 / J 推算 |
| 跟 PathPlanner 軌跡 | 理想物理下（無打滑、無延遲）跟隨誤差 ≈ 0 |

**實機只做最後驗收（G4，選用）**：需要的日誌欄位為各模組命令/實際速度與角度、驅動電流、電池電壓、陀螺儀、視覺位姿。目前程式用 SmartDashboard 輸出，要上機驗收前再補 DataLog 記錄。實機數據**不用於調整模擬參數**，只用來量化 sim-to-real 差距。

## 8. Gymnasium 介面

```python
env = SwerveAutoEnv(path="Blue3-1", n_envs=1024, randomize=True, seed=0)
obs = env.reset()                 # (n_envs, obs_dim)
obs, reward, terminated, truncated, info = env.step(action)  # action: (n_envs, 4)
```

- **觀測**：相對參考點的位置/朝向誤差（機器人座標）、估計速度、參考速度與曲率、前方 0.25/0.5/1.0 s 的參考點（相對座標）、電池電壓、上一步動作
- **終止**：真實橫向誤差 > 0.3 m（重罰）、到達終點、逾時（基準時間 × 1.5）
- `info` 回傳真實狀態、打滑量、電流，供分析與畫圖

## 9. 效能目標

- 1024 個環境、筆電 CPU、NumPy 向量化：**≥ 50,000 控制步/秒**（約 5 分鐘 1500 萬步，足夠 PPO 跑一輪實驗）
- 達不到再考慮 JAX 或 Numba，不要一開始就上

```
rl-auto/
├─ sim/
│  ├─ params.py          物理參數 + 隨機化範圍（dataclass）
│  ├─ motor.py           Kraken 模型、TalonFX 速度/位置迴路

├─ calib/                日誌讀取、參數擬合

```

## 11. 實作順序

1. `robot_software.py` + Java 對照測試（邏輯對了，物理才有意義）
2. `trajectory.py` + Java 匯出工具
3. 理想物理（無打滑、無延遲）→ 跑 PathPlanner 路線應幾乎完美跟隨（健全性檢查）
4. 加馬達模型、輪胎打滑、載重轉移，逐項加單元測試
5. 感測模型（里程計漂移、視覺）
6. 向量化 + 效能測試
7. 理論健全性檢查（§7）
